# Редактор баланса Runner

Механизм требует одной установки согласованной новой пары frontend/backend и миграции `005-balance.sql`. После установки изменение баланса через `/admin/balance/` не требует сборки, обновления образов, перезапуска приложения или перезагрузки VPS. Этот документ описывает установку; фактический рабочий сервер здесь не обновлялся.

## Что меняется

Редактор загружает определения полей с сервера: движение и бой, появление врагов, магазин, базовые характеристики, предметы и уровни, рецепты, расходники и награды. Идентификаторы предметов, число уровней и механики остаются частью кода. Денежные значения хранятся и передаются точными строками в тысячных золота: `100000` означает 100 золота.

Начальное расстояние между появлениями кандидатов магазина — 250 м; минимум и максимум равны 250. Расстояние считается непосредственно по пройденным метрам, независимо от скорости героя. Сохраняется существующее появление впереди на `spawnDistance`: при 36 м первый кандидат появляется после 250 м пробега на координате 286 м. Это интервал появления, а не обязательного входа в магазин.

Каждый новый забег получает целиком одну неизменяемую версию баланса. Награды, рецепты, характеристики экипировки и расходники не меняются при публикации другой версии, паузе, загрузке сохранения и посещении магазина. Старые забеги без ссылки на версию продолжают использовать `legacy-r34.1`. Галерея с существующим забегом показывает его настройки; без забега показывает настройки следующего старта.

## Одна установка

Использовать порядок из [R3-R4.md](R3-R4.md), сохранив существующие PostgreSQL volume и compose project. Сначала подготовить резервную копию и проверить восстановление в отдельной базе. На период установки остановить записи старой пары; новую пару включать после миграций и проверки готовности. Новые снимки имеют версию `r34.2`, а БД запрещает запись забегов через старый протокол. Смешанное обслуживание старым и новым backend не является поддерживаемым режимом.

Frontend CI должен быть закреплён на опубликованный commit именно этого backend через `deploy/backend-ref.txt`. Старый закреплённый backend не поддерживает редактор и новые снимки. Брать обе стороны из одного успешного проверенного комплекта; отдельное обновление frontend недостаточно.

На машине оператора с уже настроенными защищёнными файлами подключений:

```bash
docker compose --env-file release.r34.env -f deploy/compose.r34.yml --profile migrations run --rm migrate
docker compose --env-file release.r34.env -f deploy/compose.r34.yml exec -T postgres psql -U foxy_migrator -d foxy < deploy/runtime-grants.sql
```

Право редактора по умолчанию отсутствует у всех игроков. Оператор выбирает существующий `ACCOUNT_UUID` и выдаёт право через одноразовый контейнер мигратора; UUID не является паролем. CLI использует уже смонтированный `DATABASE_URL_FILE`, не требует копировать URL в команду или выдавать приложению доступ мигратора:

```bash
docker compose --env-file release.r34.env -f deploy/compose.r34.yml --profile migrations run --rm migrate node dist/balance/admin-cli.js grant ACCOUNT_UUID
```

Для отзыва права заменить `grant` на `revoke`. Учётную запись и право нужно назначить явно; этот репозиторий не выбирает пользователя автоматически.

Запустить новую пару, проверить backend `/readyz`, frontend `/version.json`, затем через HTTPS войти в выбранный аккаунт на `/admin/balance/`. Обычный аккаунт должен получать отказ доступа. После установки заново загрузить страницы клиентов, чтобы они получили код нового протокола.

## Дальнейшие изменения

1. Открыть `/admin/balance/` и войти в аккаунт с правом редактора.
2. Изменить поля; единицы и допустимые диапазоны показаны рядом.
3. Сохранить и получить подтверждённый номер версии. При конфликте с другим редактором черновик сохраняется; сначала загрузить актуальную версию и повторно проверить изменения.
4. Начать новый забег: он получит новую версию. Продолженный старый забег удерживает прежнюю.

Ошибочная публикация не меняет баланс частично. При недоступной БД клиент не подставляет исходные настройки. Успешная проверка `/api/v1/balance` подтверждает текущую опубликованную версию; проверка ответа нового забега подтверждает, что эта версия действительно закреплена за ним.

Для возврата настроек опубликовать прежние значения как новую версию; действующие забеги сохраняют свои версии. Возврат старых образов после миграции и появления новых снимков не является безопасным откатом. При проблеме установки выбрать совместимое исправление новой пары либо отдельно согласованное восстановление проверенной копии вместе с соответствующей парой приложений; не удалять записи миграций и историю баланса вручную.
