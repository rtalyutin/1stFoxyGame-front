# Подключение графики R4

## Файлы и координаты

Иконки, UI и эффекты: PNG 256×256, SVG с тем же полотном. Декали: PNG 512×512 из SVG с `viewBox 0 0 256 256`; геометрия масштабируется в 2 раза. Изображения имеют запас прозрачности минимум 12 пикселей на 256 и 24 пикселя на 512. Цветовое пространство PNG — sRGB, альфа прямая (straight / unassociated). Палитра совпадает с R1–R2.

В JSON атласа прямоугольники заданы в пикселях: начало сверху слева, X вправо, Y вниз. `normalized_rect_png_top_left` — X, Y, ширина, высота относительно размера атласа. `uv_bounds_blender_bottom_left` — Umin, Vmin, Umax, Vmax с началом снизу слева. Pivot каждого кадра — центр полотна. Атласы составлены без изменения пикселей исходников и без повторного наложения альфы.

Не обрезайте отдельный кадр по видимому контуру: эффект начнёт скакать из-за изменения центра. Используйте полный прямоугольник кадра. Четыре кадра соответствуют нормализованному прогрессу 0, 1/3, 2/3, 1. Частота, время и момент запуска принадлежат игре; пакет не задаёт баланс. У последовательностей нет бесконечного повтора по умолчанию.

## Интерфейс

Используйте `icons/equipment` и `icons/consumables` на общем фоне слота. Бейджи `state_owned` и `state_equipped` показывают разные факты: наличие в профиле и фактическое надевание. Не подменяйте одно другим. Совместимость проверяет игра, после чего выбирается соответствующий бейдж. `state_selected` используется только для выбранного элемента.

`slot_equipment`, `slot_consumable` и `quantity_plate` — отдельные элементы; их число и расположение задаются интерфейсом после решения по P15. Плашка количества намеренно без цифр: динамическое значение отображается поверх неё шрифтом интерфейса. Сравнение эффектов и стоимости выводится текстом из каталога/профиля. Иконки золота и компонентов берутся из R3.

Показывайте ожидание операции до ответа сервера. Эффект улучшения запускается после подтверждённого результата. Не показывайте успешное списание, улучшение или активацию только на основании нажатия. Привязки в `events.json` предложены как описание графики, а не как проверенный контракт существующего кода.

## Blender и видимая экипировка

Геометрию предметов, развёртки, риги и клипы моделей нужно создать отдельно. Декали не содержат готовой кожи персонажа и не заменяют геометрические отличия предметов. Разместите накладку на локальной UV-области предмета; смешивайте RGB декали с прежним base color по её альфе. Альфу накладки не подключайте к прозрачности всего тела: она должна управлять смешиванием цвета поверхности. Металлические, тканевые и кожаные основы возьмите из `textures/solid` и общей палитры.

Предложенные точки крепления: `weapon_hook`, `body_cuffs`, `feet_boots`, `belt_talisman`. Эти имена не проверены по моделям: сопоставьте их реальным сокетам/костям до импорта. Систему крепления выберите под фактический риг. Нарисованное деление по видам предметов не означает утверждения структуры слотов.

Один и тот же вариант предмета и уровень должны использоваться в галерее и в бою. Быстрая катушка получает 1/2/3 видимых витка, манжеты — 1/2/3 поперечных полосы, сапоги — 1/2/3 пряжки, счётчик — 1/2/3 подвески. Сохраняйте эти различия в модели, чтобы повышение уровня читалось по форме, а не только по цвету. Иконки — образцы силуэта; финальные размеры и посадка зависят от моделей.

Для проводника можно использовать цвет `sky` как маску свечения, однако эмиссивный материал, интенсивность и видимость нужно проверить в реальном освещении. Сам PNG содержит плоский цвет без запечённого свечения.

## Эффекты и игровая логика

Спрайты предназначены для прозрачных билбордов/плоскостей. След возвратного серпа нужно ориентировать по фактической траектории. Пыль и ореол расходников показываются только по состоянию эффекта, которое выдаёт игра; сила, длительность и множитель награды в изображениях отсутствуют.

Контакт сквозного зуба и возвратный след сами по себе не создают попаданий или урона. Босс сохраняет минимум три независимых попадания. Ни одна привязка графики не означает воскрешение, неуязвимость, лечение или автоматическое убийство. Часы должника в R4 имеют иконку и накладку; поведение пассивного производства и его графика относятся к R5.

## Проверка в проекте

До приёмки проверьте читаемость иконок в фактическом размере интерфейса, края с альфой на светлом и тёмном фоне, масштаб/посадку экипировки на реальном риге, одинаковый вид в галерее и бою, размещение декалей на UV и смену состояний по реальному ответу сервера. В этом пакете подтверждается подготовка файлов; фактический импорт и поведение игровой сборки требуют отдельной проверки.
