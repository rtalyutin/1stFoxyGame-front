# СЪЕЗЖАЕМ! — R1

Одиночная браузерная аркада для ПК и телефона. Дом движется сам: игрок разбирает его настоящие стены и строит из них мост к порталу. R1 добавляет серверный аккаунт, историю, восстановление между устройствами и доставку версий. Графика оригинальная, процедурные кубы Babylon.js. Лава, моб, кот, сундук и новые материалы относятся к R2.

Основание: ТЗ 0.9, редакция 4, libfile_17125a6bfc8c81918381bbbd655842aa version 2. Статус и evidence: TASK_STATE.md, evidence/qa-report.md. Репозиторий новой игры не назначен; проверяемая ревизия фиксируется SHA-256.

## Запуск

Нужны Node.js 24, PostgreSQL и отдельные подключения для миграций, игры и Auth. R1 требует HTTP/HTTPS и сервер; открытие HTML через file:// не даёт аккаунт и серверные сохранения.

```bash
npm ci
npm run check
npm run build
```

Миграция — отдельный операторский шаг server/migrate.ts; HTTP startup не выполняет DDL. Роли syezzhaem_runtime и syezzhaem_auth_runtime — группы минимальных прав. LOGIN-роли и секреты оператор задаёт отдельно. Runtime не должен наследовать владельца таблиц, superuser или BYPASSRLS. Данные находятся в syezzhaem, Auth — в syezzhaem_auth.

API требует DATABASE_URL, AUTH_DATABASE_URL, точный AUTH_ORIGIN и стабильный AUTH_SECRET от 32 символов. Production требует HTTPS, SMTP_HOST и SMTP_FROM; дополнительно SMTP_PORT, SMTP_USER, SMTP_PASSWORD. При отсутствии SMTP production не запускается. Для локальной разработки можно явно выбрать NODE_ENV=development, AUTH_MAIL_MODE=file, AUTH_MAIL_DIRECTORY: письма записываются в закрытую директорию; ссылки не выдаются через публичный API.

Конфигурация с секретами остаётся вне архива. Запуск с локальным env-файлом:

```bash
node --env-file=.env --import tsx server/index.ts
```

API слушает только loopback, порт по умолчанию 8091. SYEZZHAEM_RELEASE_ROOT — каталог опубликованных сборок, общий для API и nginx. Сначала подготовить его по deploy/README.md. npm run dev запускает Vite с прокси; origin браузера должен совпадать с AUTH_ORIGIN.

## Игра

Сними нижние блоки правой стены, накопи минимум шесть единиц дерева, подойди к краю пола и сними его крайний блок. Когда дом остановится у пропасти, построй пять клеток моста на уровне земли. Останься на доме до портала. Новый блок получает UUID; ремонт не возвращает исходный ID и долю сохранённого дома.

| Действие | ПК | Телефон |
|---|---|---|
| Ходить | A/D, стрелки | Кнопки слева |
| Прыжок | Пробел | ↥ |
| Взять | ЛКМ по блоку | «Взять», касание и отпускание |
| Поставить | ПКМ по клетке | «Строить», касание и отпускание |
| Пауза | Esc, Ⅱ | Ⅱ |

После восстановления игра стоит на паузе. При потере фокуса, повороте экрана и отмене жеста ввод сбрасывается. Можно двигаться и строить разными пальцами.

## Сохранения и версии

IndexedDB записывает снимок и очередь до HTTP-запроса. На user/run приходится неизменный inflight и последний pending; финиш не заменяется автосохранением. Неизвестный исход повторяется с прежним телом и ключом. Серверный ACK атомарно обновляет локальную revision и очередь. «На устройстве» означает успешную запись; «подтверждено сервером» — ACK конкретной команды.

Сессия и ожидаемый аккаунт проверяются сервером. Копии другого аккаунта сохраняются отдельно. При отказе IndexedDB старт блокируется, текущая игра останавливается до повторной записи. Конфликт двух устройств требует явного выбора: серверная версия, локальная копия либо отдельно подтверждённая запись по свежей revision. Завершённую историю заменить нельзя.

Забег закрепляет client_build_id, r1-map-1 и r1-rules-1. Launcher /games/syezzhaem/ выбирает закреплённую сборку; новый старт использует активную. Завершённые каталоги и динамические ассеты неизменяемы. Фронт переключается файловым указателем без перезапуска процесса/образа. Backend обновляется новым процессом: readiness, выделенный upstream, drain. Команды и восстановление — deploy/README.md.

## Проверка

```bash
npm test
npm run test:ui
```

Интеграционные тесты запускают настоящий PostgreSQL из dev-зависимости embedded-postgres. На обычном хосте нужен пользователь без root. В контейнере проверки с одним отображённым UID явно выбран OS UID shim tests/data-pg-uid-shim.c: он влияет только на запуск тестовых бинарников и проверки владельца файлов, SQL-роли/RLS не изменяются. Это не production-конфигурация. Для браузерных тестов нужен Chromium/Playwright; параметры и результаты в QA-отчёте.

Исходники: src/core.ts — симуляция; src/snapshot-v1.ts — транспорт; public/content/ — неизменяемая карта/чертёж/правила; src/main.ts — интерфейс и ввод; src/outbox.ts — очередь; server/ — Auth/API/EAV; db/ — миграции; deploy/ и scripts/ — доставка.

Локальная проверка не подтверждает установку на VPS первой игры, настоящую доставку SMTP и работу на физическом телефоне. Полный R1 gate без них не объявляется пройденным.
