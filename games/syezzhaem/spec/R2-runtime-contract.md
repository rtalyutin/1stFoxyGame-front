# R2 — полный маршрут и совместимость

Основание: `spec/TZ-Syezzhaem-v0.9-2026-10-04.md`, §§1, 3.3, 7, 8.1; Library `libfile_17125a6bfc8c81918381bbbd655842aa`, version 3. Пользователь: «давай следующий релиз выполним», 7 октября 2026. R2 реализует полный маршрут; итоговое визуальное оформление R3 остаётся отдельной поставкой.

Новая связка: build `r2-route-001`, content `r2-map-1`, rules `r2-rules-1`, level `house-full-route`. При новой публикации уже использованный build_id не переиспользуется. API v1 и snapshot schema 1 сохраняются. Условия старых `r1-map-1/r1-rules-1` и `r1-map-2/r1-rules-2` остаются прежними; старые файлы не переписаны, снимок не переименовывается в новую карту. Launcher продолжает открывать закреплённую сборку забега.

Маршрут имеет120клеток движения дома, четыре разрыва2/3/4/5клеток, порталx125. Скорость дома .65, стартовый отрыв лавы20, предупреждение потери опоры1.5сек. Дом R2 поднят доy3, чтобы обе учебные клетки были достижимы при остановленной симуляции; R1y2 не изменён. Конкретные акторы, материалы, карта, дом, правила и ссылки уровня находятся в шести новых `public/content/r2-*.json`.

На стыке опор одной высоты R2 выбирает блок по геометрии контакта и устойчивому ключу, независимо от порядка массива. Это сохраняет одинаковые опору и отскок игрока/предметов до и после загрузки. Правила приземления прежних R1 не меняются.

## SnapshotV1

Разбор строго зависит от content/rules/level. R1 сохраняет прежний набор полей: wood, actors[], lava null, timers{}. R2 требует wood/stone/slime, все устойчивые actor keys из контента, lava и полные таймеры. Ввод клавиш/жестов не восстанавливается.

R2 cell override добавляет `durability` и `burn_ticks`; tombstone содержит null, изменение прочности/горения исходного блока сохраняет его настоящий ID, замена новым блоком не возвращает original ID. Actor содержит actor_key/kind, положение/скорость, hp/state, точную опору, direction, fuse_ticks и explosion_applied. Player содержит held_actor_key и action_cooldown_ticks. Lava содержит x и интервалы урона игроку/сердцу. Counters содержат tutorial_placements и destroyed_wood/stone/slime для контроля сохранения материалов.

Сервер принимает bounded snapshot после проверки полных правил и вычисляет результат; это не симуляция каждой команды на сервере и не защита соревновательного рейтинга. Публичный рейтинг/денежные награды не входят в R2.

## EAV и миграция

Все игровые значения хранятся типизированными параметрами, не единым save_json. Новый checkpoint хранит лаву/счётчики, actor_state — движение/опору/таймер/взрыв; held_actor_ref разрешается в actor_state того же checkpoint. Все корни акторов создаются до ссылочных значений. Cell override хранит material_ref/durability/burn_ticks, inventory — три immutable material_ref. При чтении player ищется по actor_key, а не по случайному порядку UUID. CAS, очистка предыдущего checkpoint и дедупликация остаются одной транзакцией.

Метаданные расширены необязательными параметрами, поэтому старые сущности сохраняются. Старые required и ограничения не переписаны; `support_loss_ticks` остаётсяmax90, `support_loss_ticks_v2`max240 только для intro. R2 использует исходное90тиковое поле. Новые глобальные UUID21–34 имеют новые определения и ссылки на хешированные assets. R1wood_definition не меняется; R2wood/stone/slime имеют отдельные UUID. Повторный `seedR1Metadata` проверяет неизменность опубликованных определений и существующих метаданных.

`npm run migrate` — явный отдельный шаг с операторскими credentials; HTTP startup не выполняет DDL. Readiness требует метаданные и R1/intro/R2 definitions. Миграция → новый совместимый API → drain старого кода → активация immutable R2 frontend. Старый API нельзя оставлять обслуживать новые R2 записи. После появления R2 checkpoint откат на API без R2 запрещён; откат frontend pointer допустим при сохранении совместимого API и всех используемых releases.

## Проверка и ограничения

Результаты конкретного объединённого кандидата находятся в `evidence/r2-*`, хеши общих исходников — `source-provenance.json`, сборки — `build-manifest.json` после build. Успешные локальные проверки не доказывают физический телефон, аппаратные FPS, настоящую доставку SMTP или установку на целевой VPS. GitHub publication и runtime activation учитываются отдельно.
