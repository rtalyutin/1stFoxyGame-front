# Контракт реализации R1

Основание: `Runner-Forge-GDD-TZ-v1.0.md`, разделы 4–7, 10, 19–21, сценарии A01–A04/A09–A10; `Runner-Forge-Release-Plan.xls`, релиз R1. Уточнения владельца от 2026-10-02: TypeScript + Babylon.js; вертикальный телефон; касание прицеливает, отпускание выпускает хук; без сети игра не работает; графические материалы готовятся отдельно.

## Реализованное поведение

| Правило | Значение / проверка |
|---|---|
| Частота симуляции | 60 шагов/с, рендер отделён; `simulation.test.ts` сравнивает расписания 30/60 FPS |
| Движение | Вперёд 2 м/с, поперёк 6 м/с; x от −4,5 до +4,5 м; нет дискретных полос |
| Размеры | Герой 0,35 м; обычный крип 0,45 м; крюк 0,35 м — радиусы столкновений |
| Крюк | Дальность 30 м; вылет 35 м/с; возврат 45 м/с; кулдаун 2 с от запуска |
| Снимок атаки | Неизменяемые параметры и направление на `castId`; одна цель на вылете, обратный путь не наносит урон |
| Конец броска | Хук вернулся к актуальной позиции героя и кулдаун истёк |
| Крипы | Seed PRNG; непрерывный интервал 2,8–3,4 с; дальность появления 36 м; скорость навстречу в мире 1 м/с; лимит 8 |
| Поражение | Контакт живого врага или его центр за `hero.z − 1 м`; терминально для runId |
| Одновременные события | Swept collision, хронология внутри шага; при равном времени попадание раньше контакта/прорыва; стабильный ID |
| Пауза | Позиции, часы, кулдаун и генератор заморожены; захваченное тело безопасно |

В R1 поток содержит только обычных крипов. Усложнение со стрелками и боссами относится к R2.

Переходы текущего среза: `BOOT → GALLERY → COUNTDOWN → RUNNING`; из боя — `PAUSED` или `GAME_OVER`; продолжение — через новый отсчёт, рестарт — новый `runId` и seed. `GALLERY` в R1 является стартовым экраном одного фиксированного героя; полноценная галерея относится к R6. Значения `SHOP`/`WORKSHOP` предусмотрены в типе приложения для будущих переходов, содержимое не реализовано.

Выход из боя очищает удержанные клавиши, очередь команд и незавершённое сенсорное прицеливание. `pointercancel` не выпускает хук. Нажатие на HUD не атакует. Уже летящий хук сохраняется при паузе. После возврата нужно новое нажатие. При длительной остановке главного потока (>0,5 с) включается системная пауза вместо скрытого продвижения врагов.

## Сетевой контракт

`GET /api/v1/health`, тот же origin, запрос `cache: no-store`:

```json
{ "status": "ok", "apiVersion": "1", "serverTime": "2026-10-02T12:00:00.000Z" }
```

Только успешный HTTP-ответ совместимой версии допускает старт/продолжение. Интервал проверки — 2 секунды после завершения запроса, timeout — 3 секунды. Отсутствие связи обнаруживается максимум за 5 секунд после последнего успешного ответа; событие браузера `offline` ставит на паузу сразу. Возврат связи не возобновляет бой. Нажатие «Продолжить» ждёт свежий ответ и затем запускает отсчёт. `navigator.onLine` сам по себе доступ не предоставляет. Старый ответ после события offline не разблокирует игру.

R1 проверяет связь, но сервер пока не ведёт авторитетную симуляцию и не сохраняет результаты. Эта граница не является защитой от изменения клиента или начисления наград: в R1 наград нет. Аккаунты/сессии/персистентная экономика реализуются в R3 по backend-контракту; публичная регистрация не планируется.

## Временная сцена и контракт моделей

Сейчас `WorldView.buildHero/buildEnemy` создают геометрический blockout. Камера следует за миром позади героя; декорации продолжаются за шириной пути, рамки игрового поля нет. HTML HUD показывает дистанцию, число убийств и готовность крюка. Тёплый крюк/прицел выделяется на холодном фоне; силуэт обычного крипа выделен формой и светлым лицом. Это решение для проверки читаемости, а не утверждённый финальный арт.

Контракт для отдельно производимых файлов:

- Формат GLB/glTF 2.0, метры, Y вверх, модель смотрит в +Z. Корень `hero_root` в точке земли между стопами, без встроенного перемещения по маршруту. Финальный импортёр GLB не входит в текущий blockout.
- Герой `pudge`, ability `meat_hook`; рост временного силуэта около 2,3 м. Коллайдер берётся из конфигурации симуляции и не выводится из размера меша.
- Узлы крепления: `socket_hook_hand` (правая кисть), `socket_weapon`, `socket_head`, `socket_body`, `socket_feet`. Крюк — отдельный узел/модель, цепь соединяет актуальную кисть и текущую позицию хука. Временная привязка кисти: локально `(0.72, 1.15, 0.25)`.
- Имена клипов: `idle`, `run`, `strafe_left`, `strafe_right`, `hook_cast`, `hook_hold`, `hook_return_empty`, `hook_return_capture`, `death`. Будущие магазин/галерея подключаются позже. Движение root-motion выключено; клип не меняет игровую позицию и не задерживает отключение опасного коллайдера.
- Крип: root `enemy_root`, клипы `run`, `hit`, `death_capture`. После события `hit` с убийством тело сразу безопасно; визуальное завершение не возвращает коллайдер.
- Стандартные PBR-материалы без обязательного custom shader, текстуры до 2048 px, совместимый вариант меньшего разрешения для телефона. Бюджет полигонов/текстур и финальные размеры проверяются после получения реальных файлов на целевых устройствах.
- События адаптера: `cast`, `castRejected`, `hit`, `returned`, `spawn`, `gameOver`; позы читаются из снимка симуляции. `state.events` содержит только текущий логический шаг: потребитель, читающий несколько шагов за кадр, должен собрать события каждого шага. Сцена R1 читает итоговое состояние.

## Проверки и ограничения

Авторские автоматические проверки: `npm test` — механика, порядок событий, пауза, seed, повторный бросок, сеть; `npm run build` — строгая типизация и production bundle. Двухпальцевое управление, читаемость портретного HUD, lifecycle и доступность API дополнительно проверяются в браузере на конкретной сборке. Автотесты не заменяют ручной тест на настоящем Android.

Готовые модели, звук, серверные сохранения, Android/desktop wrappers и измерение производительности конечных устройств не входят в этот срез. Зафиксированные зависимости и инструкции запуска не означают, что тестовый адрес уже опубликован.
