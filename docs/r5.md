# Runner R5 — мастерская

Экономика хранится на backend. Клиент показывает подтверждённый общий кошелёк, производства, доход в секунду, стоимость следующей постройки и следующий уровень улучшения. Ни таймер, ни локальное хранилище не начисляют золото. Стартовые числа задаются серверным балансом; в редакторе `/admin/balance/` появилась группа «Мастерская».

## Экраны и возвращение

Кнопка «В мастерскую» доступна в галерее, на итогах и в подтверждённом магазине своего забега. Во время боя, отсчёта и обычной паузы мастерская не открывается. «Вернуться» восстанавливает исходный безопасный экран; выход из мастерской в магазин не продолжает движение. Если другое устройство изменило забег, клиент возвращается к паузе и требует явного продолжения.

Скрытая вкладка не выполняет опрос. Возврат в мастерскую или магазин сохраняет тот же экран и запрашивает серверное начисление. При восстановлении страницы сначала проверяется сессия и ожидающая операция, затем начисляется доход. Подтверждённые начисления показываются отдельно; при превышении лимита указаны учтённое и отброшенное время. В мастерской кошелёк обновляется сервером после каждого действия. Видимые меню, мастерская и пауза запрашивают начисление раз в 15 секунд; открытая пауза не считается длительным офлайном. В бою начисление выполняется вместе с уже существующими серверными пакетами кадров.

## Операции и ошибки

Чтение `/api/v1/workshop` не изменяет имущество. Начисление, ручной удар, постройка и улучшение используют общую очередь `/api/v1/operations` с `operationId`, `expectedRevision` и `clientId`. Цены и результат удара берутся из серверного ответа. Покупка передаёт опубликованную `balanceRevision`; изменение цены требует обновить данные и заново нажать кнопку. Клиент не повторяет отказанную покупку самостоятельно.

При неизвестном результате клиент хранит только ту же ожидающую команду, блокирует новые действия и проверяет её квитанцию. Повтор запроса не создаёт второй удар или покупку. Выход из аккаунта исключает запоздавшие ответы старого аккаунта. Исторические квитанции без поля `workshop` остаются совместимыми; отдельное чтение загружает современное представление без повторного начисления.

## Две области баланса

Боевые правила, рецепты экипировки и параметры эффекта «Часов должника» закрепляются за забегом. Настройки мастерской — цены производств, ставки, сила удара, улучшения и лимит офлайна — начинают действовать сразу после публикации. Backend хранит историю ставок и делит начисление по времени публикаций. Клиент не пересчитывает прошлые периоды по текущей ставке.

Старые сохранения без `compiled.forge` и старые каталоги без часов продолжают загружаться. Имущество нового R5 не теряется при таком сохранении; часы не добавляют эффект старому забегу. Их рецепт появляется в магазине нового забега. Представление часов в этом выпуске функциональное: имя, рецепт, слот и описание эффекта в существующем интерфейсе экипировки.

## Проверка пары

Из checkout frontend при backend в соседнем каталоге:

```sh
BACKEND_CATALOG_PATH=../r5-back/content/catalog.json npm test
BACKEND_ROOT_PATH=../r5-back npm run validate:r34-pair
npm run build
```

Проверяются точные денежные строки, полный формат мастерской, восстановление того же запроса, устаревшие ответы, старая экипировка и безопасный адрес возврата. Браузерная приёмка должна дополнительно пройти ручной удар, покупку, конфликт опубликованной цены, неизвестный результат, фон/возврат, магазин, результаты и мобильный экран. Сборка подтверждает код; она сама не подтверждает установку на VPS.

Для установки нужна совместимая пара R5 и серверная миграция `006-forge.sql`. Старую пару нельзя одновременно оставлять писателем экономики. Существующие PostgreSQL volume, аккаунты, кошелёк и история баланса сохраняются; порядок резервной копии, остановки писателей и миграций остаётся в [документации установки](../deploy/BALANCE.md).

Перед проверкой опубликованного комплекта `deploy/backend-ref.txt` должен содержать реальный опубликованный commit backend R5. Прежний commit R3/R4 не подходит к каталогу с часами и API мастерской. Локальная проверка через `BACKEND_ROOT_PATH` подтверждает рабочую пару исходников, но не заменяет закрепление опубликованного backend в CI и установке.
