# R3/R4 — профиль, магазин, экипировка; без новой графики

Основание: Runner-Forge-Release-Plan.xls (Library libfile_cbf1e74c70bc81919c5ef53b2835cbee) и GDD v1.0 (libfile_cb543b0ba1a881919b5604fcefd7c054); запрос 03.10.2026 «Реализуй релиз 3 и 4. Без графики».

Стартовые допущения реализации: выданные логин/пароль без публичной регистрации, аккаунты создаются контролируемым миграционным CLI из защищённого файла; 30-дневная отзываемая HttpOnly-сессия, ручная ротация пароля оператором. Один активный клиент на аккаунт; второй читает и может явно забрать управление, при этом бой ставится на паузу. Без сети бой стоит. Несовместимый снимок закрывается с объяснением, постоянное имущество остаётся. P13–P16 применяются как конфигурируемые стартовые правила ТЗ, а не результат балансировочного теста.

Условия: сохранить модели/камеру и все новые графические файлы чужого main 5afb5541840cffda3a9516d7ed033e94cb647dd5 без изменений. Новые модели, текстуры, VFX, видимые крепления экипировки и макеты исключены запросом; функциональные формы/кнопки используют существующий стиль. F23 и графические части D10–D17/B19/O14 не считаются реализованными. Мастерская/производство/Часы должника — R5; дополнительные герои — R6. Продакшен не меняется.

Профиль хранится в PostgreSQL 18 через действующий типизированный конструктор entities/entity_parameters/entity_parameter_values. Снимок симуляции и журнал операций — технические записи; они не заменяют доменные типизированные значения кошелька, владения предметами и сборки. GoldMilli — десятичная строка неотрицательного целого, 1000 единиц = 1 золото.

Экономика, награда и снимок боевого результата коммитятся одной транзакцией. Нет клиентских команд начислить валюту или объявить убийство: сервер переигрывает фиксированные шаги детерминированной симуляции. Все команды имеют operationId и expectedRevision; повтор идентичной команды возвращает сохранённый результат, изменённая команда под тем же ID отклоняется. Профиль одного аккаунта блокируется на время записи. Клиентский кеш не является кошельком.

Контракт API: /api/v1/auth/login {login,password}; /auth/logout; GET /session -> {account:{id,login},csrfToken,expiresAt}; GET /profile -> Profile; GET /economy/catalog -> EquipmentCatalog; GET /run?clientId=UUID -> RunView|null; POST /operations -> OperationResult; GET /operations/:operationId -> сохранённый OperationResult. Все пути имеют префикс /api/v1. Изменяющие операции сессии требуют X-CSRF-Token. Same-origin JSON, HttpOnly/SameSite=Strict cookie; Secure в production. Login не создаёт аккаунт.

Profile = {accountId,revision,goldMilli,components:{steel,ember,core},items:[{id,definitionId,level}],loadouts:{pudge:{weapon,body,legs,talisman,quick:[definitionId|null,definitionId|null]}},consumables:{slow_dust,collector_vial},stats:{runs,totalKills,bestDistance}}. Слоты содержат instanceId|null. EquipmentCatalog имеет version r34.1, items и consumables с рецептами/уровнями/модификаторами из §14. Начальный баланс и инвентарь пустые. Старые R2 каталоги/health не ломаются.

Operation = {operationId:UUID,expectedRevision:integer,clientId:UUID,type,payload}. Types: start_run {}; advance_run {runId,ownerEpoch,frames:Command[][]}; pause_run/resume_run/leave_shop/end_run {runId,ownerEpoch}; takeover_run {runId}; craft {definitionId}; upgrade {itemId}; equip {slot,itemId|null}; quick_slots {slots:[definitionId|null,definitionId|null]}; consume {runId,ownerEpoch,definitionId}. OperationResult = {operationId,status:'committed',profile,run:RunView|null,replayed:boolean}. RunView = {runId:UUID,loot:{goldMilli,components},snapshot:SimulationSnapshot,control:'owner'|'readOnly',ownerEpoch,updatedAt}. Ошибка {error:{code,message}}. Коды 401 доступа, 403 права/CSRF, 409 stale/conflict/busy, 422 правила, 503 unavailable. clientId отличает вкладки; чужой accountId не принимается в запросах.

Симуляция сохраняет весь RNG и счётчики; exportSnapshot()/static restore(snapshot), snapshot.state содержит RunState. Дополнительные методы setEquipment(modifiers), canEnterShop/shop(id), enterShop(id), leaveShop(), applyConsumable(definitionId), abandon(). Команда enterShop с shopId и необязательным offset 0..FIXED_STEP обрабатывается как событие точного времени. Магазин и снаряды/хук/телеграфы/кулдауны заморожены; смерть на том же timestamp выше входа. Есть usedShopIds. Каст копирует параметры и множество уже поражённых целей; босс получает максимум одну метку за castId. serialize/restore продолжает тот же поток. modifiers = {rangeMultiplier,outboundSpeedMultiplier,returnSpeedMultiplier,cooldown,lateralSpeedMultiplier,pierceTargets,returnHitTargets,goldMultiplierMilli}. Базовые значения берутся из DEFAULT_CONFIG, не накапливаются при переодевании.

Бой на клиенте оптимистичен, сервер пересчитывает batches <=120 фиксированных кадров, проверяет порядок владельца/версию/скорость продвижения по серверному времени и возвращает авторитетный снимок. При неопределённом ответе проверяется тот же operationId; перезагрузка предлагает продолжение серверного снимка через явное подтверждение и отсчёт. Второй клиент не пишет без явной передачи.

Приёмка: реальные PostgreSQL ограничения/повторы/конкуренция/перезапуск/backup-restore; авторизация и чужой аккаунт; крафт со всеми ресурсами и нехваткой одного; магазин/пауза/смерть в одном шаге; snapshot/RNG roundtrip; экипировка следующего каста; pierce/return и минимум три каста босса; 3→2 расходника после применения и смерти; браузерный цикл login→run→shop→craft/equip→continue→death→reload. Сборка пары и CI относятся к точным ревизиям, не подтверждают установку на VPS.

При незавершённом забеге любые операции профиля (крафт, улучшение, экипировка, быстрые слоты) доступны только активному clientId. Второй клиент может читать и явно перехватить управление. После gameOver галерея доступна всем клиентам с проверкой revision.

RunView дополнительно содержит независимый runId и loot (goldMilli, components) с подтверждёнными наградами этого забега. Метаданные доступны даже при повреждённом snapshot и позволяют закрыть только забег; итоговая добыча показывается отдельно от постоянного кошелька.

Дублирование вкладки: живые документы различают clientId через BroadcastChannel; скопированная вкладка получает новый UUID и удаляет копию ожидающей команды до чтения/записи API. Одновременные claims разрешаются по nonce. Без BroadcastChannel новый документ получает новый clientId; продолжение старого забега требует явного takeover. Кошелёк в браузере не хранится.
