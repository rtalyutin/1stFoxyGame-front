# FoxyGames: общий 3D-зал

Публичный статический хаб `/hub/` рядом с первой игрой `/`. Backend, API, аккаунты и runtime Node.js ему не нужны. [Исходный контракт v1.1](requirements.md) сохранён как вход реализации, без заявления о выполнении всех AC. Текущие продуктовые допущения исполнителя: общий лис и самостоятельная страница игры после входа. Пользователь пока не выбрал OQ01/OQ02; это открытые решения, а не согласованный бесшовный переход.

## Запуск и сборка

Node.js — из корневого `.nvmrc`, зависимости — из общего lockfile.

```sh
npm ci
npm run hub:dev
# http://localhost:5174/hub/
npm run hub:test
npm run hub:build
```

Сборка: `hub/dist/index.html` и `hub/dist/releases/<build_id>/`. Входной HTML уже содержит весь каталог, описания и настоящие ссылки. JS, GLB, постеры и манифесты принадлежат одной неизменяемой версии. Идентификатор по умолчанию — хеш исходников хаба; для поставки можно задать `HUB_BUILD_ID` и `SOURCE_SHA`. `dist` не коммитится. Первая игра продолжает собираться прежней командой `npm run build`.

`npm run hub:test:browser` поднимает Vite и Playwright в одном процессе. Перед ним установить штатный браузер: `npx playwright install chromium ffmpeg`. Для существующего совместимого тестового бинарника предусмотрен `HUB_BROWSER_EXECUTABLE_PATH`. Этот режим включает SwiftShader и не заменяет проверку физического GPU. Результаты, снимки и запись — в игнорируемом `test-results/hub/`.

Только dev-server поддерживает `?fixture=0|1|2|3|10|12`. Записи для масштаба — технические копии реальных сцен, в опубликованный HTML они не попадают. `?entry-test` в dev возвращает контроллер в IDLE после события вместо навигации. Сборка игнорирует оба параметра. `window.hubDebug` существует только в dev.

## Поведение

- Один native-scroll ряд: 3 полных элемента на широком экране, 2 на планшете, 1 на телефоне; при переполнении виден край следующего. Стрелки делают один шаг, клавиатура работает на сфокусированном каталоге; вертикальное колесо и zoom не перехватываются. Диапазон вычисляется по DOM, позиция хранится по ID в `sessionStorage` с безопасным отказом.
- Один Babylon Engine/canvas/Scene. Общий пол, кладка, светильники и реальные тени; корпуса и объёмные миры импортируются из GLB. Нативная геометрия DOM задаёт размещение, включая частично видимый автомат. Герой проходит наклонный мост через настоящий проём. Кадр, состояние и движение управляются одним циклом.
- Миры живут без наведения: лис бежит по кузнице, рыцари обходят замок, кот и тележка движутся около дома. Мосты, кристаллы и блоки выступают из проёма. Невидимые соседи подготовлены, но не симулируются; удалённые контейнеры освобождаются. Выбор удержан уже с PREPARING; отмена инвалидирует старые загрузки и повторный вход.
- Reduced motion останавливает движение и оставляет статическую 3D-сцену с прямыми ссылками. Без JS/WebGL остаются постеры и HTML-каталог. При отказе отдельной сцены появляется явный «Открыть игру» и повтор загрузки; другие миры продолжаются. Потеря контекста останавливает вход, восстановление возвращает IDLE. При browser Back не возникает повторной навигации.

## Каталог и модели

`hub/games.json` — единственный список: Runner Forge, Last Throne, Съезжаем!. В первой поставке адрес Runner — `/`, две будущие игры имеют `soon` и `launchPath:null`. Это маршрут из пользовательского контекста и существующего приложения; действующую серверную доступность надо перепроверить при установке. Проектные `/td/` и `/games/syezzhaem/` пока не публикуются как доступные.

`hub/config.json` задаёт `entryMode: url|event` и текущего общего героя. `event` — технический обработчик `hub:entry-complete`, который сам не встраивает полноценную игру. Для героя другой игры требуется GLB с тем же контрактом, ссылкой в манифесте и новой проверкой масштаба/габаритов; одна смена текста в конфиге не создаёт риг.

Манифест сцены имеет версию 1, GLB, проверенный модуль поведения (`forge|throne|moving`), GLB героя и три anchors. GLB должен содержать `cabinet_root`, `screen_opening`, `anchor_approach`, `anchor_entry`, `anchor_inside`; герой — `hero_root`, `idle`, `run`. Сборка отклоняет плохой каталог, URL, манифест и отсутствующие файлы; тесты импортируют все реальные модели и проверяют узлы, клипы и трансформации поведения.

Редактируемый авторский источник — `hub/assets/generate_models.py`: Python 3, без пакетов, Y up, метры, передняя сторона -Z. Это оригинальные параметрические low-poly модели, а не экспорт изображений макета. GLB можно импортировать и править в Blender. После правок источника:

```sh
python hub/assets/generate_models.py
python hub/assets/render_posters.py # Pillow, только офлайн mesh-render резерва
npm run hub:test
```

Клип пробежки привязан к фактически пройденной длине, с отдельной фазой опоры/подъёма стопы. Финальная точка учитывает габариты головы и задник. Художественная точность относительно растрового макета и постановка ног требуют визуальной приёмки; структурный импорт их не доказывает. Исходники и ассеты созданы для этой поставки; внешние модели, CDN и сторонние текстуры не используются.

Добавление игры: подготовить мир/корпус и при необходимости модуль поведения, anchors/маршрут, героя/клипы, резервный постер, манифест и запись каталога. Затем тесты и сборка. `playable` назначается после проверки реально размещённой игры; путь должен быть на том же origin. Карусель и счётчик править не требуется.

### Подключение готовой Last Throne R2

Исходники клиента добавлены в `games/last-throne/web`; core и сервер — в парном backend-репозитории. Основной `hub/games.json` сохраняет `soon`: наличие кода не подтверждает работу `/td/` на сервере. После установки и серверной приёмки создайте проверенный каталог вне исходников:

```sh
node hub/scripts/activate-last-throne.mjs --origin https://actual-origin --out /private/path/td-catalog.json
HUB_CATALOG_FILE=/private/path/td-catalog.json npm run hub:build
```

Проверка требует действующий HTTPS origin первой игры, готовый R2 API, точный `r2-001` в launcher/bootstrap, согласованные версии и capabilities, content ETag, известный projectionHash R2 и SHA256 всех клиентских файлов из неизменяемого манифеста. Redirect, несовпадение или ошибка прекращают активацию. Команда не меняет сервер, исходный каталог и другие игры; существующий выходной файл не перезаписывает. Это техническая проверка доступности, а полный проход игры и сохранения проверяются отдельно.

`HUB_CATALOG_FILE` используется Vite и сборкой; его содержимое входит в идентификатор hub и `version.json`. Для каждого нового результата задавайте новый путь либо удаляйте только свой временный файл после проверки. Сборка без переменной сохраняет «Скоро». Затем опубликуйте весь полученный `hub/dist/` штатным `publish.sh` и проверьте вход через автомат. При откате hub используйте `rollback.sh`; игровые releases и сохранения не удаляются. `npm run hub:build` включает Node-тесты отказов этой процедуры.

## Установка рядом с играми

Предложенные пути `/srv/foxygames/hub/` и HTTPS origin ещё не обследованы в этой поставке. Установка на сервер не выполнялась.

1. Проверить актуальные Nginx `server/location`, корень первой игры, API/другие префиксы, mounts, права чтения и место. Проверить Service Worker первой игры и его область, в том числе в тёплом профиле; не очищать чужие данные.
2. Рассмотреть `deploy/hub.nginx.conf.example` внутри существующего HTTPS server. Разрешены только новые hub-prefix rules. Stable HTML — `no-store`, `open_file_cache off`; versioned ресурсы — immutable. Неизвестные hub-файлы должны давать 404, учитывая наследуемые `error_page`. Общий родитель releases должен быть доступен веб-серверу.
3. Для первоначальной конфигурации — штатная проверка Nginx и graceful reload. Для последующих версий только доставка статических файлов, без reload/restart.
4. Доставить весь `hub/dist/` во временный артефакт на host, затем выполнить:

```sh
bash hub/scripts/publish.sh /path/to/artifact /srv/foxygames/hub https://actual-origin
# Откат входа, без удаления releases и без изменений игр:
bash hub/scripts/rollback.sh /srv/foxygames/hub https://actual-origin
```

Publish сериализован flock, проверяет SHA256 локальных и HTTP-ресурсов до смены входа, запрещает перезапись готовой версии и атомарно заменяет стабильный index. До переключения доставка может оборваться без потери старого входа. Предыдущий HTML и все releases сохраняются; автоматической очистки нет. После переключения проверить headers, тёплый и новый браузер, позднюю загрузку старой вкладки, игровые URL и API до/после в одинаковом охвате. Два последних шага — серверная приёмка, а не результат локальной сборки.

## Границы проверки

Автотесты покрывают данные, геометрию, отмену/повторы, ресурсные поколения, импорт всех GLB и реальные трансформации миров. Браузерный раннер покрывает DOM/3D, ширины и размер каталога, вход, late load, context, reduced motion, no-JS и число ресурсов; фактический отчёт — [verification.md](verification.md).

Приёмка на физических Chrome/Edge/Firefox, iPhone Safari и Android Chrome, точные стопы/перекрытия, отказ восстановления, bfcache, память GPU и серверные AC12–14 остаются отдельными проверками. Нельзя объявлять стабильный FPS на устройствах по headless SwiftShader. OQ01/OQ02 также остаются неподтверждёнными пользователем.
